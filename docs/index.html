Install & Repositories

Barq is split into one repository for the language and one for each package. The language runs on its own; the framework and the packages plug into it when they are installed. Everything is pure Python 3 with no dependencies.

RepositoryWhat it holdsNeeds
barqThe language: compiler, VM, REPL, standard library (Database, Http, Route, Session, templates, Storage, uploads, Mail, Queue, Test…), barq fmt, barq check, barq servePython 3
barq-frameworkModels (ORM), migrations, seeders, factories, the service container, providers, events, the scheduler, make:*barq
barq-authGuards, Gate and policies, API tokens, password resets, email verification, 2FA, OAuth login, teams, devices, auth:installbarq-framework
barq-permissionsRoles, permissions, wildcards, team roles, role: / permission: middlewarebarq-auth
vscode-barqVS Code extension: highlighting, format on save, inline errors, outline, snippetsbarq

terminal 
# the language
git clone https://github.com/barq-lang/barq
barq/bin/barq run barq/examples/hello.bq

# the framework and packages: clone them next to barq/
git clone https://github.com/barq-lang/barq-framework
git clone https://github.com/barq-lang/barq-auth
git clone https://github.com/barq-lang/barq-permissions
barq/bin/barq packages        # barq-framework, barq-auth, barq-permissions

The barq command finds packages that sit next to the barq checkout, in the folders listed in BARQ_PATH, or anywhere Python can import them. BARQ_PACKAGES=none turns them all off; BARQ_PACKAGES=barq_framework loads only that one (and what it needs).

New in v0.23.0-alpha: the karo type

Function values now have the type karo instead of function, so one word covers declaring and passing functions: karo applyTwice(karo kr, int value) then return kr(kr(value)). karo and kr are keywords only where they start a function; elsewhere kr is an ordinary name.

barq build makes a dist/ folder to deploy: your app with every file already compiled, a copy of Barq and the packages it uses, and a start script (start.cmd on Windows). The server only needs Python 3. Run dist/barq migrate, then dist/start. Tests, .env, databases and uploaded files are left out; --zip packs the folder into one file.

Packages are git repositories on GitHub. barq install acme/strings picks the newest tagged version that fits, puts it in vendor/ and pins the exact commit in barq.lock; after that use Acme\Strings\Shout just works. Constraints like @^1.2, @~1.2.3 or @main, plus barq update, barq remove and barq publish (checks your package and tags its version). barq-framework, barq-auth and barq-permissions install the same way.

barq new my-app starts a web app with routes, a controller, views, config, an .env with its own APP_KEY and passing tests. --api makes a JSON-only app, --console a program, and --auth adds login, registration and the rest of barq-auth. With barq-framework installed it also gets the User model, its migration, a factory and a seeder, so barq migrate and barq serve work straight away.

Design Goals

  1. Readability over cleverness. Code reads like structured English. Python's indentation rules apply everywhere.
  2. Full-stack from day one. No separate templating language. The runtime handles server responses and browser output.
  3. Database as first-class citizen. Official drivers for every major database, uniform query API across engines.
  4. Strict typing. Type declarations are mandatory. The compiler catches type errors, undefined variables, and logic errors before any code runs.
  5. No external dependencies. Every feature lives in Barq's own standard library.
  6. Familiar to PHP and Python developers. OOP structure mirrors PHP; control flow mirrors Python.
  7. Cross-platform from day one. The same .bq source runs on Linux, macOS, and Windows without modification.
  8. Eats its own cooking. The official website, documentation, and package registry are all built in Barq.

Security

Barq is secure by design. Security is not a plugin or an afterthought — it is enforced by the compiler and runtime.

FeatureHow it works
Strict typingAll variables must have explicit type declarations. The compiler rejects mismatches before execution.
Pre-execution checkingCompiler checks types, undefined variables, unreachable code, and logic errors before any code runs.
No implicit coercionint + string is a compile error. Explicit casting required: string(x).
SQL injection preventionQuery builder uses parameterized queries by default. Raw SQL requires explicit db.raw() with bound parameters.
XSS protectionAll template output is HTML-escaped by default. Unescaped output requires explicit opt-in.
CSRF protectionFramework validates CSRF tokens on all POST / PUT / DELETE routes automatically.
Input validationBarq\Validation sanitizes and validates all user input.
Secure cryptoBarq\Crypto and Barq\Hash use proven algorithms (bcrypt, AES-256, SHA-256).
No evalThere is no eval() function. Dynamic code execution is not possible by design.

Performance

Barq is designed to be significantly faster than PHP and Python for web workloads.

  • Bytecode compilation — .bq source compiled to bytecode on first run, cached as .bqc
  • No startup interpreter overhead — VM loads cached bytecode directly
  • Built-in HTTP server — no Apache/Nginx layer needed for development
  • Zero external packages at runtime — no dependency resolution at startup
  • Connection pooling built in — database connections pooled automatically
  • Ahead-of-time type checking — when types are declared, the VM uses optimized paths
BenchmarkPHP 8.3Python 3.12Barq Target
Simple HTTP response~1 ms~2 ms< 0.5 ms
DB query + render~5 ms~8 ms< 2 ms
JSON API response~2 ms~3 ms< 1 ms

These are design targets, not measured benchmarks.

Multi-line Strings & Long Lines

"""…""" strings span lines and interpolate; '''…''' strings are literal. The indentation all lines share is removed, along with the line break after the opening quotes and a last line holding only the closing quotes. A line ending in an operator (+, and, ??, =…) carries on to the next line.

Nullable Types

🟡
Implemented in v0.13 — provisional

int, float and bool never hold null. Put ? in front of a type when null is allowed. string, collections and classes already accept null, so ?User mainly tells the reader to expect it.

nullable.bq 
?int age = null
?int count                       // no value: null (int count starts at 0)

    return id == 1 ? new User("Ali") : null

print(find(2)?.name ?? "nobody")
int years = age ?? 0
int x = null   // error: variable 'x' is int and cannot be null — make it ?int to allow null

Anonymous Functions & Lambdas

✅
Decided — two ways to write a function without a name

Anonymous function karo(params): type with an indented body · Lambda kr(params): type => expr for a single expression

closures.bq 
// Anonymous function — karo(...) with a body on the next lines
any process = karo(string name): string
    string upper = Str.upper(name)
    return "Hello, {upper}"

// Anonymous function passed as argument
list<int> result = items.map(karo(int x): int
    int doubled = x * 2
    return doubled
)

// Lambda — kr(...) for a single expression; function values have the type karo
karo double = kr(int n): int => n * 2
list<int> doubled = items.map(kr(int x): int => x * 2)

Function values have the type karo (v0.22; it was function before): any callable value — a named function, a lambda, a bound method like counter.bump, or a built-in — so parameters can say they expect one: karo applyTwice(karo kr, int value) then return kr(kr(value)). karo and kr are keywords only where they start a function; elsewhere karo is the type and kr an ordinary name.

Defaults, Named Arguments & Variadics

🟡
Implemented in v0.12 — provisional

Default values are constants · named arguments go after positional ones · *int numbers collects the rest into a list<int> · f(*list) spreads a list

arguments.bq 
#[string]
karo greet(string name = "World", string greeting = "Hello")
    return "{greeting}, {name}!"

greet()                            // Hello, World!
greet("Ali", greeting: "Salaam")   // Salaam, Ali!
new User(name: "Ali", age: 30)      // constructors take named arguments too

#[int]
karo sum(*int numbers)            // numbers is a list<int>
    return numbers.reduce(kr(int a, int b): int => a + b, 0)

sum(1, 2, 3)                       // 6
list<int> more = #[4, 5]
sum(*more, 6)                       // 15 — *list spreads into the arguments

Defaults are worked out on every call, so list<int> seen = #[] is a fresh list each time. Built-in functions take positional arguments only. Route handlers can rely on defaults too: karo index(Request req, int page = 1) serves /posts and /posts/:page.

Enums

An enum is a type with a fixed set of named cases, like PHP 8.1. A pure enum has cases only; a backed enum — #[String] or #[Int] on the line above enum Status — gives every case a unique value — handy for database columns and JSON.

enums.bq 
enum Suit
    case Hearts
    case Spades

#[String]
enum Status
    case Active = "active"
    case Banned = "banned"

    #[Public]
    #[string]
    karo label()
        return this == Status::Active ? "Can log in" : "Blocked"

Status s = Status::Active
print(s.name, s.value, s.label())     // Active active Can log in
Status::from("banned")              // Status::Banned
Status::tryFrom("deleted")          // null
Status::cases()                       // #[Status::Active, Status::Banned]
MemberPureBackedReturns
Enum::Case✅✅The case
case.name✅✅string
case.value—✅int or string
Enum::cases()✅✅All cases, in order
Enum::from(v)—✅Matching case, or raises ValueException
Enum::tryFrom(v)—✅Matching case, or null

Enums are types (Status s, list<Suit>), compare with ==, work in switch, sets and as dict keys, and can have methods, static methods and constants — but no properties. Cases are read-only, new Status() is an error, and Json.encode() writes a backed case as its value.

Interfaces

An interface lists methods (signatures only, always public) and constants. A class names it after implements and must provide every method — checked when the class loads. Interfaces are types, work with is and except, and can be bound in the container.

interfaces.bq 
interface Shape
    const UNIT = "cm"

    #[float]
    karo area()

class Square extends Figure implements Shape, Named
    #[void]
    karo __construct(public float side = 1.0)   // constructor promotion
        return

    #[float]
    karo area()
        return this.side * this.side

list<Shape> shapes = #[new Square(2.0), new Square()]
print(shapes[0] is Shape, Shape::UNIT)     // true cm

Traits & Constructor Promotion

A trait's properties, methods and constants are copied into every class that writes use TraitName — as if they were written there, so private members, self:: and __class__ refer to that class, and each class keeps its own static values. A method written in the class wins. The same method from two traits is an error, unless a rule under the use line picks one (below).

traits.bq 
trait HasSlug
    public list<string> history = #[]

    #[string]
    karo slug()
        return Str.slug(this.slugSource())

    #[Abstract]
    #[string]
    karo slugSource()             // the class must provide it

class Article
    use HasSlug, Timestamps

    #[void]
    karo __construct(public string title)   // declares and assigns this.title
        return

    #[string]
    karo slugSource()
        return this.title

Conflict rules (v0.13). PHP's insteadof and as, written in an indented block under the use line. An alias can still reach the method that insteadof dropped.

trait-rules.bq 
class Person
    use Hello, Salaam
        Hello::greet insteadof Salaam   // Hello's greet() wins
        Salaam::greet as salaam         // Salaam's stays reachable as salaam()
        wave as protected               // new visibility
        wave as public waveHi           // a renamed copy

Routing

Routes map a method and a path to a handler: a function, or #[Controller, "method"]. Write parameters as :id. Inside "double quotes", {id} would be string interpolation, so the {id} form only works in 'single quotes'.

main.bq 
use App\Controllers\UserController

Route.get("/", kr(): string => "<h1>Home</h1>").name("home")
Route.get("/users/:id", #[UserController, "show"]).whereNumber("id")
Route.post("/users", #[UserController, "store"])

// Handler arguments are filled by type: Request, then route parameters
Route.get("/sum/:a/:b", kr(int a, int b): int => a + b)

Route.serve(#{"port": 8000})
resources & groups 
// index, create, store, show, edit, update, destroy — whichever the controller has
Route.resource("users", UserController)

// Group with a URL prefix, middleware and a name prefix
Route.group(#{"prefix": "api/v1", "middleware": "auth", "name": "api."}, karo(): void
    Route.get("/profile", #[UserController, "profile"]).name("profile")
)

Route.url("api.profile")   // returns /api/v1/profile

Auth, Storage & Scheduler

Auth logs users in with a session (the web guard) or a Bearer token (the api guard). Gate and policies decide what a user may do. Passwords are checked against Hash.password() hashes.

routes/web.bq 
Route.post("/login", karo(Request req): any
    if Auth.attempt(#{"email": req.input("email"), "password": req.input("password")})
        return Response.redirect("/dashboard")
    return Response.redirect("/login")
).middleware("guest")

Route.get("/dashboard", kr(Request req): string => "Hi " + req.user().name).middleware("auth")
Route.put("/posts/:post", #[PostController, "update"]).middleware(#["auth", "can:update,post"])
Route.get("/api/me", kr(): any => Auth.user()).middleware("auth:api")

NewAccessToken t = user.createToken("cli", #["posts:read"])

You get registration, login with "remember me", logout, forgotten-password emails, email verification and two-factor authentication with a QR code and recovery codes.

Roles & permissions

Give users roles, give roles permissions, and check them anywhere: in code, in routes and in views. user.can() asks the permissions first, so the Gate, policies and the can: middleware all see them. A granted posts.* covers posts.create, and the super admin role passes every check.

terminal 
barq permissions:install      # tables migration, config/permissions.bq, an example seeder
barq migrate
barq permissions:assign-role ali@shop.test admin
Roles, permissions and checks 
Role editor = Role.create("editor")
editor.givePermissionTo("edit posts", "publish posts")

user.assignRole("editor")
user.givePermissionTo("delete posts")       // directly, without a role
user.hasRole("editor")                     // true
user.can("publish posts")                  // true: through the editor role
user.assignRole("admin", team: acme)        // only inside one team

Route.get("/admin", ...).middleware("role:admin")
Route.put("/posts/:id", ...).middleware("permission:edit posts|publish posts")

<if condition="{auth().user().hasRole('admin')}">...</if>
✅
Built in v0.16.0-alpha — now in barq-permissions

Also: barq permissions:list-roles, list-permissions, show-role, show-user, create-role, create-permission and cache-reset. Any model can have roles, and permissions can be given for one guard (web, api) or one team.

REST API

app/Controllers/Api/PostController.bq 
namespace App\Controllers\Api

use App\Models\Post
use App\Resources\PostResource

class PostController

    #[Public]
    #[Response]
    karo index()
        posts = Post.orderBy("created_at", "desc").paginate(20)
        return PostResource.collection(posts)

    #[Public]
    #[PostResource]
    karo show(int id)
        post = Post.findOrFail(id)
        return new PostResource(post)

    #[Public]
    #[PostResource]
    karo store(PostStoreRequest request)
        post = Post.create(request.validated())
        return new PostResource(post)

    #[Public]
    #[Response]
    karo destroy(int id)
        Post.findOrFail(id).delete()
        return response().json(#{message: "Deleted"})
